# OPAAL 1.0

This specification defines conformance for OPAAL 1.0 source processors and for the explicit project workflow. A conforming source processor parses, analyzes, and evaluates the language within the stated refusal and resource rules. A conforming project frontend applies the manifest, authority, artifact, and host-boundary rules when it offers check, plan, execute, or audit. A host adapter conforms only for the operations and enforcement verdicts it actually implements; conformance does not imply that every host supports every effect.

In this document, **MUST** and **MUST NOT** are requirements for those subjects. **SHOULD** marks an expected behavior for which a documented, justified exception can exist. **MAY** marks an optional capability that cannot weaken a MUST requirement. A reference page may describe a shipped parser or serializer in greater field-level detail, but it cannot create a second semantic rule.

## Source identity and evaluation

A source processor MUST treat a UTF-8 `.opaal` file as ordinary OPAAL source without a version directive or source-mode selector. Local imports MUST be explicit quoted `.opaal` paths with aliases. Standard imports MUST resolve only to compiled `std::` identities; project identities MUST exist only under an explicitly selected project. The processor MUST NOT search ambient package paths or interpret an unknown bare name as a host executable.

A bare name MUST resolve through the visible language or registered command namespace. External-program syntax MUST use a literal `^` head; a dynamic executable head is not part of OPAAL 1.0. A command interpolation MUST evaluate its expression once. A spread MUST consume one list and emit separate eligible arguments without recursive flattening.

A block MUST yield its final non-terminated expression. Empty blocks, declarations, terminated expressions, and loops yield `Null`; a selected `if` or `match` block retains its value. `return` exits the current callable. Nominal construction MUST supply every declared field exactly once, and nominal matches MUST use the same canonical identity. A closed unguarded match MUST be checked for missing and unreachable arms. Value streams MUST remain typed, lazy, and single-consumer under deterministic limits and cleanup.

A processor MUST distinguish completed values or carriers, catchable language errors, cooperative cancellation, classified refusal, and fatal host or reporting failure. It MUST preserve ordered partial-effect and cleanup evidence without replacing the primary outcome. It MUST charge source, analysis, and evaluation budgets as documented in [limits](../reference/limits.md); crossing a bound MUST NOT yield a completed partial program.

## Actions and permission

An action MUST declare typed parameters, an explicit result, and its closed effect requests. Analysis MUST reject a cycle, undeclared reachable callee effect, action value, function-to-action call, or invalid project scope. A task MUST appear only in the manifest-selected root module and export one action without changing its signature or effects.

An effect declaration MUST NOT grant authority. Ordinary script and interactive evaluation MUST refuse an effectful invocation before platform access. A project check MUST compare the selected task's requests with exact environment authority and target enforcement without invoking the action, reading a secret, probing a tool, or calling an operational adapter. Missing or explicitly denied rows MUST deny. Unknown and unsupported enforcement MUST NOT be treated as executable. An unenforced process request MAY execute only where the maintained adapter can bind the parent boundary and its exact grant acknowledges the unenforced child internals.

## Project and evidence

A project frontend MUST require an explicit path to a regular `opaal.toml`; it MUST NOT infer selection from the working directory, parent directories, an editor root, or source imports. The closed project, authority, and lock documents MUST be validated against the selected project and environment. Project file access MUST remain beneath retained roots without following symlinks. Control reads MUST obey their per-file and aggregate limits.

Plan creation MUST bind the checked task, typed inputs, source closure, authority, tool lock, child environment, platform, toolchain, TLS material, exact executables, and expiry into one canonical artifact. It MUST NOT invoke the action, probe a tool, read a secret, or contact an endpoint. A refused plan MAY be stored for inspection but MUST NOT be executed. The four v2 schema names identify artifact formats and MUST NOT be interpreted as source-language version selectors.

Execute MUST require the complete plan digest as request-local acceptance and MUST revalidate bound identities and expiry before the task receives a controlled host. It MUST NOT use a separately persisted acceptance state or resume an earlier run. An admitted run MUST write one exclusive, synced, hash-chained journal with ordered action, effect, cleanup, and terminal evidence. Secret material MUST NOT be stored in journal payloads. External effects MUST NOT be implicitly retried.

Audit MUST validate the closed journal schema, contiguous sequence, digests, chain, and terminal ordering without executing or resuming work. A valid complete-line prefix without a terminal MUST become an incomplete audit; earlier corruption MUST refuse a success claim. Journal and audit evidence MUST NOT be described as a transaction, generic rollback, or external attestation.

The [reference](../reference/README.md) gives accepted syntax, command signatures, format fields, limits, and host-specific verdicts. Its examples do not broaden this contract.
