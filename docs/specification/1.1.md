# OPAAL 1.1

OPAAL 1.1 inherits the [1.0 specification](1.0.md) except for the ordinary
source authority rule replaced here. This version permits explicit foreground
external programs in the standalone `opaal SCRIPT` and interactive `opaal`
clients. Project check, plan, accept, execute, and audit retain their separate
controlled contract and artifact formats.

## Direct external programs

A CLI session MUST take one complete native working directory and environment
snapshot before evaluation. It MUST preserve every valid native environment
name and value or fail before evaluation. A snapshot MUST admit at most
1,000,000 entries and 16 MiB of combined native name and value bytes. A
snapshot with duplicate native environment names MUST refuse rather than
silently replace an entry. A source `cd`, `export`, or `unset` changes only the
retained session context. The snapshot entry and byte ceilings apply when the
session is created; they are not reapplied to later `export` mutations.

Only a literal caret head, such as `^program`, MAY select an external program.
An unknown bare head MUST NOT search for an executable. The client MUST resolve
the expanded native head directly, without a shell, using the session working
directory and ordered native `PATH`. Relative direct paths and relative `PATH`
elements MUST be probed and spawned against that same working directory; empty
`PATH` elements MUST be skipped. A `PATH` search MUST refuse a `PATH` exceeding
1 MiB or 4,096 elements before probing. A direct head containing `/` does not
consult `PATH`. A probe MUST follow symlinks and
require a regular executable target under effective host credentials. Probe
acceptance is advisory: spawn after a race is authoritative and MUST NOT fall
back to another candidate. Argument expansion MUST preserve empty, spaced,
Unicode, and native byte arguments.

The CLI's ambient process mode MUST admit only foreground caret stages,
explicit redirections, and the following commands when connected to an external
stage: `check`, `decode`, `from`, `encode`, `to`, `first`, `last`, `collect`,
`length`, `lines`, `each`, `where`, `select`, `get`, `update`, and `sort`.
The context controls `cd`, `pwd`, `export`, and `unset`, plus existing `help`
and `exit`, MAY run in that mode. `env()`, `glob()`, `which`, `ls`, `open`,
`save`, operational module calls, effectful actions, background launch, and
`jobs`, `fg`, `bg`, `wait`, and `kill` MUST retain their pre-host refusal.
An import, declaration, or effect annotation MUST NOT grant ambient authority.

The first 4,096 child starts in one standalone run or interactive submission
MAY proceed; the first excess MUST refuse before a probe or spawn. The existing
stream carrier, redirect, pipeline, and `Status` contracts apply. Child stdout
and stderr inherited by the CLI MUST stream without an invented OPAAL byte
ceiling or retention by OPAAL. Captured carriers retain their existing byte
limits. A process failure or nonzero status MUST NOT be reported as a
successful zero status, and diagnostics MUST remain on stderr.

An OPAAL-owned foreground process group MUST be cleaned up after normal
completion, startup or wait failure, and supported `SIGINT`, `SIGTERM`, and
`SIGHUP` routes. After one of those signals reaches the group, OPAAL MUST allow
two seconds for it to end, then send `SIGKILL` to the owned group if it remains
active. This grace period is not an automatic execution timeout. Interactive
foreground terminal ownership MUST return to the client after the group ends.
Forced host death and a descendant that deliberately leaves the owned process
group are outside this guarantee.

## Authority and conformance

An ambient child inherits the session environment, which may contain
credentials. It can perform opaque filesystem, network, or device effects
permitted to the OS user. OPAAL provides no sandbox, child-output redaction,
audit, declared-tool identity, retry, rollback, or containment of escaped
descendants for this route. The CLI does not load a `.env` file or restrict
program names to a whitelist. A child may daemonize and leave the owned group.
Users SHOULD minimize the child environment and MAY use `unset` before invoking
a program.

Static check, plan inspection, formatting, help, and language-server analysis
MUST NOT probe or spawn a program. Existing embedding constructors MUST remain
deny by default; an embedding MUST deliberately supply a host-enabled context
to obtain ambient execution. Controlled project execution MUST continue to
require its accepted plan, authority, host verdict, and evidence. In
particular, the Linux-only exact-identity project process route does not gain a
macOS grant from the direct CLI route.

This direct contract is qualified on Linux x86_64 and macOS arm64. It creates
no claim for another host or a physical device. The [limits](../reference/limits.md),
[command reference](../reference/language/commands-pipelines-and-streams.md),
and [security model](../concepts/security-model.md) provide lookup details.
