# Actions, effects, and authority

An action declaration answers one question: which effects can this call graph request? It does not answer whether those requests are allowed. Static analysis follows calls, rejects cycles and undeclared callee effects, and attaches the closed request set to a task.

A project environment answers the next question with exact authority rows. An absent row denies the request; a matching grant still needs the adapter to establish its boundary. For a file, that means opening beneath the retained root without following symlinks. For an endpoint, it means the declared method and TLS identity. For a process, OPAAL can bind the executable and child environment on Linux, but it cannot confine the child's own filesystem or network behavior. The process grant therefore acknowledges that remaining gap explicitly.

Check reports the combined verdict without running the action. Plan captures the exact task, grants, target, and control identities for review. Execute receives authority only through the one accepted plan request and revalidates those identities before work. Ordinary source never acquires the controlled host by importing a project name or by constructing an effectful action.

[Actions and effects](../reference/language/actions-and-effects.md), [authority](../reference/operational/authority.md), and the [capability matrix](../reference/operational/capability-matrix.md) state the individual rules.
